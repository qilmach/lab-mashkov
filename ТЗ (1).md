# Технічне завдання: Telegram-бот розкладу занять

## 1. Вступ
Telegram-бот, який показує розклад занять групи або викладача, беручи дані з сайту розкладу навчального закладу. Має веб-адмінку для зв'язку з користувачами.

## 2. Мета і задачі
- **Мета:** дати студентам і викладачам швидкий доступ до розкладу в месенджері.
- **Основні задачі:**
  - отримання розкладу групи та викладача з сайту (парсинг HTML);
  - розпізнавання різних форм запису назви групи (`ПД-11-26`, `пд1126`);
  - збереження групи/викладача для швидкого доступу;
  - веб-адмінка для перегляду діалогів і відправки повідомлень;
  - збереження користувачів та історії повідомлень у БД.

## 3. Цільова аудиторія
- **Студент:** обирає «Розклад групи», вводить групу, обирає день, отримує розклад; зберігає групу.
- **Викладач:** вводить прізвище й отримує розклад на тиждень.
- **Адміністратор:** у `/admin` читає діалоги та відповідає користувачам.

## 4. Функціональні вимоги
1. **Команда `/start`** — вітання, головне меню, реєстрація користувача. *Приймання:* користувач з'являється в таблиці `users`, відповідь за ≤ 2 с.
2. **Розклад групи** — введення групи, нормалізація назви, вибір дня. *Приймання:* `пд1126` і `ПД-11-26` дають однаковий результат; для невідомої групи є зрозуміле повідомлення.
3. **Розклад викладача** — пошук за «Іванов», «Іванов І», «Іванов Іван». *Приймання:* показано час, групу, аудиторію.
4. **Збереження запиту** — кнопки «Зберегти / Не зберігати», швидка кнопка в меню. *Приймання:* після перезапуску бота збережена кнопка на місці.
5. **Кнопка «На головну»** — скидає поточний крок діалогу. *Приймання:* працює на будь-якому кроці.
6. **Веб-адмінка** — список користувачів із пошуком, історія діалогу, відправка повідомлення. *Приймання:* повідомлення доходить у Telegram і записується в історію.
7. **Логування** — усі повідомлення пишуться в БД. *Приймання:* збій БД не блокує відповідь бота.

## 5. Нефункціональні вимоги
- **Продуктивність:** відповідь на `/start` < 2 с, розклад < 10 с.
- **Надійність:** SQLite у режимі WAL, обробка недоступності сайту розкладу.
- **Безпека:** токени лише у змінних оточення, адмінка під захистом (Basic Auth у v1.1.0).
- **Сумісність:** Python 3.10+, Linux/Windows, будь-який клієнт Telegram.
- **Логування:** модуль `logging`.

## 6. Обмеження та припущення
- Немає офіційного API розкладу, тому парсинг залежить від розмітки сайту.
- Стек: Python, pyTelegramBotAPI, BeautifulSoup/cloudscraper, Flask, SQLite, pyngrok.
- Розробник один, перший реліз за 3 тижні.

## 7. Інтерфейс користувача
```
/start → Головне меню
  ├─ Розклад групи    → введення групи → вибір дня → розклад → Зберегти?
  ├─ Розклад викладача → введення ПІБ  → вибір дня → розклад → Зберегти?
  └─ 📌 Збережена група / викладач
На кожному кроці доступна кнопка «🏠 На головну».
```

## 8. Архітектурні рішення
```
Telegram ⇄ бот (long polling) → SQLite (users, saved_queries, messages)
                 └→ сайт розкладу (парсинг)
Адмін → ngrok → Flask (/admin) → SQLite
```
Один Python-процес (потік polling + Flask на порту 8080). CI/CD — GitHub Actions. Деплой — VPS або локальна машина, налаштування через `.env`.

## 9. План робіт та етапи
- **Ітерація 1 (тиждень 1):** каркас бота, `/start`, БД, розклад групи.
- **Ітерація 2 (тиждень 2):** розклад викладача, збереження запитів, «На головну».
- **Ітерація 3 (тиждень 3):** адмінка, винесення токенів у `.env`, CI, документація.
- **Реліз 1.0.0:** стабілізація, тег `v1.0.0`.

## 10. Критерії приймання
- Виконані вимоги F1–F7 за критеріями розділу 4.
- Тест-кейси: (1) `/start` показує меню; (2) група `пд1126` дає розклад, `абв` — повідомлення про помилку; (3) викладач `Іванов` дає розклад; (4) збережена група зберігається після перезапуску; (5) повідомлення з адмінки доходить у Telegram; (6) при недоступному сайті бот не падає.
- У репозиторії немає токенів.

## 11. Додатки
Схема БД: `users(telegram_id, username, first_name)`, `saved_queries(id, telegram_id, query_type, query_value)`, `messages(id, telegram_id, text, sender, timestamp)`.
