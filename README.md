## Як перевірити
1. Прочитати `ТЗ.md` (11 розділів) і `VERSIONING.md`.
2. Перевірити Git-історію:
   ```bash
   git log --graph --oneline --all --decorate
   git tag -n          # має бути v1.0.0
   git branch -a       # main, develop, feature/*
   ```
3. Запуск бота (код у `src/bot.py`, якщо додано до репозиторію):
   ```bash
   pip install -r requirements.txt
   export TELEGRAM_TOKEN=...   # токен від @BotFather
   python src/bot.py
   ```
   Токени не зберігаються в репозиторії, лише у змінних оточення.

## Вибір моделі життєвого циклу: Agile (Scrum) + CI/CD
Проєкт невеликий, розробник один, вимоги уточнюються за відгуками користувачів, а бот залежить від стороннього сайту розкладу, розмітка якого може змінитися. Тому Waterfall не підходить, а короткі тижневі ітерації дають робочий продукт і швидкий зворотний зв'язок.

- **Спринт:** 1 тиждень. Planning у понеділок, review (демо) у п'ятницю, ретроспектива 15 хв.
- **Артефакти:** product backlog (функції F1–F7 з ТЗ та ідеї), sprint backlog (задачі спринту), increment (працюючий бот), Definition of Done (`ACCEPTANCE_CHECKLIST.md`).
- **Ризики:** зміна розмітки сайту (ізольований парсер і тести), блокування запитів (cloudscraper, кеш), витік токенів (`.env`), розробник один (документація).

| Спринт | Результат |
|---|---|
| 1 | Каркас, `/start`, БД, розклад групи |
| 2 | Розклад викладача, збережені запити |
| 3 | Адмінка, `.env`, CI, реліз `v1.0.0` |
